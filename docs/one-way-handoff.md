# One-way operational handoff
Generic orangerank-handoff-v1 payload, Bearer auth and stable Idempotency-Key header remain unchanged. Only HTTP200 means TRANSPORT_ACCEPTED; no body/ledger acknowledgement required. Assessment remains financially PAYMENT_CONFIRMED, not started/completed/QA/delivered. Validation-only path remains separate.

Atomic operational claim requires PENDING_INTEGRATION and no prior operational attempt. It saves SEND_INTENT_RECORDED, unique attempt ID, timestamp and lease before network. Repeated calls never retransmit, including expired leases. Expired intent becomes OUTCOME_UNKNOWN; timeouts/network/non200 responses also hold. Receipt persistence failure returns OUTCOME_UNKNOWN; persisted intent prevents resend. If receipt actually committed, subsequent calls see TRANSPORT_ACCEPTED. A process crash may leave SEND_INTENT_RECORDED until an operator reads/reconciles it; drain skips it. This conservative behavior can strand an unsent request after a pre-send crash; never automatically repair/retry it.

Operators must reconcile ambiguous attempts using authoritative receiver evidence before any separately approved new attempt. No reconciliation endpoint/migration introduced. Legacy outbox DISPATCHING/RETRY_PENDING/ACKNOWLEDGED states are not automatically converted or resent; require review. No exactly-once receiver guarantee is claimed. Production resources untouched.

First sandbox prerequisites: explicit Preview test mode, approved checkout gates/origin, correct test Price/signing secret/Redis; generic receiver enabled with verified endpoint/token and dedicated dispatcher credential; new clear-identity owned consistent non-synthetic assessment; exact-ID authorization and queue disposition independently confirmed; separately approved single manual dispatch. No automatic generic invocation from payment webhook. No config activation or live request performed in implementation.
